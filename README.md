# 针对 Qwen2.5-VL 的对抗"停车"补丁 
（更新于 11/06/2026 · 目标模型自始至终为 Qwen2.5-VL-3B-Instruct）

一句话：从"迁移碰运气、还分不清是不是补丁起效"（名义 57.5% / 真攻击仅 7.5%），
做到"白盒直接攻 Qwen、被当成真 STOP 标志、对没见过的图与多种 prompt 都成立"
（决策 100% / 感知 ~100% / 真攻击 ~62–72%）。

## 一、路线图
① 复现 + 发现迁移天花板
   原方法：白盒在 CLIP 上训补丁 → 黑盒"迁移"到 Qwen。复现后发现 STOP 决策率最高 ~57.5%，看运气、不稳。

② 关键洞察：决策攻击被"场景"混淆（最重要的一步）
   停下可能是 (a) 把补丁当成 STOP 标志，也可能是 (b) 觉得场景危险而保守地停。
   测试集已人工排除真实 STOP 标志 ⇒ "模型说看到 STOP 标志" ≡ 补丁起效。
   归因评估一查：迁移补丁 57.5% 的停里，真·因标志只有 7.5%，其余是"场景吓的"。名义成功率虚高。

③ 目标（Goal B）：让补丁压过环境 —— 模型要"因为感知到补丁=STOP 标志"而停，且能泛化。

④ 方法转向：从"迁移"到"白盒直接打 Qwen"
   直接用 Qwen 自己的梯度。核心工程：用 torch 逐位复刻 Qwen 的归一化+patchify（max|diff|=0），
   让梯度精确回传到 64×64 补丁像素；冻结全部权重、只训补丁；先做显存探针确认 11GB 跑得动。

⑤ 结果（in-sample）：1 个 epoch 就把 40 张全翻成 STOP（vs 迁移 57.5%）。

⑥ 验证它是"真的"（归因）：白盒补丁 100% 让模型回答"有 STOP 标志"，~72% 明确因它而停（vs 迁移 7.5%）。
   而且补丁本身是纯噪声、人眼完全不像标志 —— 纯对抗的感知攻击。

⑦ 证明能泛化：在 100 张 data/train 上训练、在从没见过的 40 张上测（md5 校验 0 重叠），
   仍 100% STOP / ~98% 感知 / ~63% 真攻击 —— 不是过拟合，是真·通用补丁。

⑧ 工程稳健 + 独立复现：训练做成数值稳健（异常梯度清零 + 裁剪 + 固定种子），整套结果已被独立复现。

⑨ 划定适用边界：把补丁过一遍多种 prompt（含硬 prompt），明确"100%"的适用范围（见三）。

## 二、核心数字（40 张"无真实 STOP 标志"图）
| 补丁                | STOP决策率 | 感知"有STOP标志"(yes/no) | 真实攻击(停&因标志) |
|---------------------|-----------|--------------------------|--------------------|
| clean（不贴）       | 0.150     | 0.000                    | 0.000              |
| 迁移（原方法）       | 0.575     | 0.025                    | 0.075              |
| 白盒 patch（主）    | 1.000     | 1.000                    | 0.725              |
| 泛化 patch（heldout）| 1.000     | 0.975                    | 0.625              |
注：真实攻击率为关键词分类的"保守下限"；感知率才是干净指标（≈100%）。

> ⚠️ **命名澄清（重要，别被 "in-sample" 坑到）**：上面两行是**两块不同补丁**——
> `qwen_stop_patch.png`（主/白盒）与 `qwen_heldout_patch.png`（泛化）。在归因评测
> `eval_attr_full.py` → `attribution.csv` 里，**两块都评在同一批 40 张留出（manifest）图上**（各 40 行）。
> 所以旧标签 "白盒 in-sample" 里的 "in-sample" **只是补丁身份、不是评测集**：那个 `.725`
> 其实是**主补丁在留出图上**的成绩，**不是**"在训练图上评"，也**不是**"同一块补丁 train vs test"。
> 同批直接比：**主补丁 .725 > 泛化补丁 .625**——即主补丁自己在留出图上就泛化得更好，
> 专门训一块"泛化补丁"的收益存疑。（决策 STOP 率两者都 1.000；`.725/.625` 是归因后的因果率。）

## 三、跨 prompt 适用边界（硬-prompt 实验）
逐 prompt 翻转数（40 张，**两列都评在 data/test 留出图上**；目标 Qwen2.5-VL-3B；项目原版中文 prompt）：
| Prompt                      | clean | 白盒patch（主）  | 泛化patch（heldout）    |
|-----------------------------|-------|------------------|-------------------------|
| decision_stop_or_go（二选一）| 0/40  | 39/40            | 40/40                   |
| decision_risk（信号/风险）   | 10/40 | 40/40            | 39/40                   |
| decision_safe_action（开放式）| 4/40 | 21/40 (52.5%)    | 34/40 (85%)             |
| sign_stop（描述停止标志）    | 1/40  | 40/40 是STOP标志 | 5/40 是STOP标志(+25泛标志)|
| sign_presence（描述标志）    | 0/40  | 28/40 是STOP标志 | 6/40 是STOP标志(+32泛标志)|
| 汇总 action_asr             | 0.10  | 1.00             | 1.00                    |
| 汇总 risk_asr               | 0.25  | 1.00             | 0.975                   |
| 汇总 sign_asr               | 0.025 | 1.00             | 0.225                   |

> ⚠️ **同二节的命名坑**：这两列是**两块不同补丁**（`qwen_stop_patch.png` / `qwen_heldout_patch.png`），
> `eval_qwen_multprompt_patch.py` **只吃 `qwen_eval_manifest.json` = data/test**，所以**两列都评在留出 40 张上**
> （已核：所有 multprompt 结果 CSV 共 4832 行全是 `data/test`）。旧列名 "in-sample" 是**补丁身份、不是训练集内评测**。
> 另注：**"whitebox/heldout" 在本项目有两套义**——此处（Qwen 文档）指"主补丁/泛化补丁"；而迁移评测 CSV 里
> `whitebox_center`=集成攻击、`heldout_center`=Qwen 单模型基线，**词同义不同，勿混**。

读法：
- 决策层：两张白盒补丁在"未见图 + 多种 prompt 框架"下都稳（action_asr=1.0，各决策 prompt ≥85%）；
  泛化补丁在开放式 safe_action 上反而更强（85% vs 52.5%）。
- 感知层：in-sample 是字面"STOP 标志"（sign_asr 1.0）；泛化补丁偏"泛标志幻觉"（sign_asr 0.225），
  但直接 yes/no 问"有没有 STOP 标志"它仍答 97.5%——差别在描述粒度，不矛盾。
- 取舍：训练集多样性 ↑ ⇒ 决策更鲁棒、感知更"泛"。
- 注脚：作者英文 risk prompt（强调 hazard）更抗；我们中文 prompt（"信号或风险"）易翻 —— 跨 prompt 鲁棒性部分依赖措辞。

## 四、三个方法贡献
1. 区分"名义决策攻击"与"真因果攻击"，用感知归因揭示迁移补丁虚高（57.5%→真 7.5%）。
2. 白盒可微管线：逐位复刻 VLM 预处理，使"直接对 Qwen 求梯度优化补丁"成为可能，突破迁移天花板。
3. 泛化与边界：disjoint train/test 证明通用性；多 prompt 实验厘清适用范围。

## 五、诚实边界
固定居中 · 干净数字域（无 JPEG/物理拍照）· 单模型 Qwen2.5-VL-3B · 贪心解码 · "真攻击率"为保守下限。
下一步可做：EOT（随机位置/缩放/亮度/压缩）走物理可用；跨模型迁移；作者原版英文 prompt 逐字对比。
